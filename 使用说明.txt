店小秘 Temu 自动上架 · 独立版 1.7.4（2026-10-30）

本次修复：原图尺寸正确却仍提示服装图片尺寸不足
1350×1800处理设置正常生效。网页的颜色图片预览失败时，会把该图宽高记录清空，发布校验按0处理，可能错误提示小于1340×1785。
1.7.4会将只读核验成功的原图字节供原浏览器图片重新加载，保持原地址、内容和顺序，让网站自己的加载事件登记真实尺寸。只有网页图片真正就绪才允许继续，不再仅凭程序读到原图尺寸放行。
不伪造网页尺寸、不修改Vue内部数据，也不为恢复预览重新上传图片。
这条规则校验颜色轮播图，不是描述图片。1350×1800及“保留模板不变”可以继续使用。
失败现场另存image-diagnostics.json，记录本批处理设置及网页当时的实际加载尺寸；站点提供可读模型时也记录其宽高，以便准确定位。
已有成功完成记录保留。关闭旧版后使用新版，仅重试失败项，核对图片和发布模式再开始。

保留1.7.3：上传后的缩略图加载与批次恢复（恢复后网页必须真正就绪）
图片已生成图库地址，但网页缩略图偶发加载失败时，程序会有限重载预览；仍未加载的图片可只读获取原地址并完整解码，继续核对实际尺寸。不会因预览失败重新上传整款。
仍严格核对图片数量、不同图片地址和处理后的尺寸，正常加载但尺寸错误的图片不会被忽略。
若一款上传仍未确认，该款保留失败记录，本批次暂停自动删除图库图片。只读确认图库空间充足时，其余商品可继续；空间不足或无法核实时停止。
暂停删除状态随保护记录保存，重新开始或继续待处理不会自动解除；不会因换批次而删除尚未确认的上传图片。
图片保护记录写入失败、当前页面关闭、图库删除结果不明确等保护仍保留。
升级不会启动上架、删除图片或清空完成记录。先关闭旧版，再运行新版；真正失败的商品用重试入口，未处理商品用继续按钮。

保留1.7.2修复：失败记录与待处理商品
主窗口“失败 / 待处理”分别显示当前目录、当前脚本、模板及货号对应的失败数量和待处理数量。
打开后显示当前目录可处理总数、已有完成记录数、失败数、待处理数，另列历史失败数量。
失败记录默认只看当前目录；切换“全部历史”可查看其他目录、脚本、模板或货号的历史失败。
“待处理商品”页列出没有完成记录且不在当前失败列表的商品。图库检查或模板问题中断后，剩余商品会出现在这里，不会误计为逐款失败。
点击“继续当前目录待处理商品”，核对当前设置和图片后继续；使用单页、每款一次，严格跳过已有完成记录，并排除当前失败列表。真正的失败请用重试入口处理。
结果不明确的提交需要先到店小秘核对，不会自动重试；移除其失败记录也不能绕过核对。
选择一条或多条历史失败，点击“移除选中失败记录”可隐藏旧记录；只改变记录显示状态，保留商品、失败现场及完成记录。
主窗口的一键重试仅重试当前目录失败。历史列表的重试会核对脚本、模板、货号，并明确提示未纳入原因及数量。
商品首次处理异常时立即保存失败记录；后来重试提交成功才解决记录，发布前检查通过仍保留记录。
修复首次失败重试询问未正确调用的问题，恢复手动选择及两分钟默认重试规则。
程序的完成记录表示已确认提交或安排定时；店小秘后台最终上架状态仍需在店小秘查看。
升级保留原有登录、配置、完成记录和素材，不要清除完成记录来继续中断任务。

保留1.7.1修复
店小秘图库返回“系统繁忙（2005）”、临时服务错误或连接超时时，只读检查最多尝试3次，间隔2秒、4秒；恢复后继续，不立即停批。
权限、登录、未知格式错误不盲目重试；错误信息会显示接口路径、代码和平台原因。删除请求始终不自动重发。
兼容图库中没有显示名称的有效图片；图片ID、所属账号、锁定状态及网址核验继续保留。
空间检查在每款商品上传前执行，任务中途低于触发线同样自动处理，并非只在任务开头检查一次。
如果单款正在上传时网站明确提示图片空间不足，立即停止整批，当前款及后续商品保留待处理，已完成项不重跑。
单款上传可能部分成功且未显示到页面，因此此时不会边清理边自动重传；请人工处理空间后重新开始，不要清空完成记录。

保留1.7.0功能
新增可选的“图库空间不足时自动清理”，默认关闭，默认触发线按本次要求为低于100MB，可修改为50–2000MB。
需要时在主窗口勾选开启。程序在每款上传前读取真实剩余空间，低于触发线时按每页300张计算，只从当前末两页的固定名单中清理。
每次最多600张，末页不足300张按实际数量；例如1279张时，清理范围最多79+300=379张，不从更前页补足600。
跳过已锁定图片、当前模板图片和本批次已使用的图片；每批清理后核对删除结果与剩余容量，空间已达到目标就提前停止。
下款上传原文件总量加10MB预留如果大于触发线，会提前按这个预留量检查空间。最多仍只处理末两页，不会连续向前删除更多页。
开启后本批次使用1个工作页，避免上传和清理同时进行；关闭后恢复原来保存的并行页设置。
删除不可恢复，旧的待发布/发布失败商品、部分在线商品或合规标签仍可能引用图库图片。只在确认末页旧图允许删除时开启。
本批次保护不能判断所有历史商品的引用关系；网站“未锁定”不等于图片未被使用。需要长期保留的旧图请先在店小秘图库中锁定。
读取失败、登录变化、图片范围变化、清理后空间仍不足或删除结果不明确时，整批停止，剩余商品保留为待处理，不会逐款报失败或继续扩大删除范围。
删除请求不会自动重发；结果不明确的记录会阻止后续自动清理，需要人工核对。可先关闭自动清理、人工处理空间后继续。
运行日志目录下 album-cleanup 保存本次选定ID、数量、容量前后值和保护记录；不要打包转发个人日志。
更新保留原来的登录、配置、货号、完成记录和图片排序。环境自检不访问真实图库，也不执行删除。

保留1.6.0功能
新增“图片混合排序”，商品图和细节图在同一个窗口显示，可自由穿插排列。
例如：商品图1 → 细节图1 → 商品图2 → 细节图2 → 商品图3。
操作：先选择商品目录、添加需要的细节图，再点主窗口右上角“图片混合排序”；选择缩略图后使用前移、后移或置首，最后点“保存排序”。
第一张实际上传的图片就是主图，细节图也可以置首；运行前请核对缩略图和主图标记。
“将当前混排方式应用到同类全部商品”可批量套用位置：每款仍使用自己的商品图，不复制当前款的商品图片。
保存的批量位置也会用于以后新加入的商品文件夹；单独调整某款并保存时，该款使用自己的顺序。
黑白T恤分别选择“商品名·白色”和“商品名·黑色”，各自混排、各自应用批量；不会把白图或细节传到黑色组。
“黑白对应”只调整两张原始商品图的颜色对应，实际上传顺序由“图片混合排序”确定。
图片过多时，窗口会标明“本次上传”和“上限未选”；每色最多10张，保留细节图并按混排顺序选入商品图。
未设置混排的旧配置继续按原来的商品图在前、细节图在后的顺序；取消窗口不保存修改。
更换细节文件后失效位置会自动忽略，新图片追加到当前顺序末尾；如需新的穿插位置，请重新混排保存。
原有图像处理模式、描述保留模式、登录和完成记录均保留；升级不会自动重跑已完成商品。

保留1.5.0功能
新增“图片处理”选项，毛毯、普通T恤、黑白T恤及细节图统一使用本次选择。
“保留原图（不处理）”：直接上传原文件，不转换JPG，不修改本地图片尺寸、比例或文件内容。
“按比例缩小”：设置最长边（例如1200），大图等比缩小，小图不放大、不补白，输出JPG。
例如2400×1600设置最长边1200后为1200×800，原本600×400的小图仍为600×400。
“填充到指定尺寸”：可分别填写宽和高，图片等比缩放适应画布，空白处补白，不裁剪，输出JPG。
例如1200×1200会成为1:1画布，也可设置800×1000等矩形尺寸。可选800/1200/1600，也可输入200–4000的整数像素。
旧版和新配置默认仍为“填充到指定尺寸1200×1200”；希望保持原比例且不处理时，请主动选择“保留原图（不处理）”。
运行前核对窗口会显示处理方式，以及每张图的原尺寸→预计上传尺寸；原始文件始终不被覆盖。
选项在扫描或运行时保存，下一次打开会继续使用；批次开始后的修改用于下一批，自动补跑沿用当前批次设置。
以上选项控制本程序的本地处理，店小秘接收文件后可能另行处理图片。它不是按文件体积设置压缩率。

保留1.4.0功能
黑白T恤现在分为“白色细节图”和“黑色细节图”，分别添加、预览排序和清空。
白色行上传白色主图＋白色细节图，黑色行上传黑色主图＋黑色细节图；每组最多9张细节图，互不占用数量。
两组都支持从不同文件夹多次追加、同一路径去重及单张移除；尺码图等确实共用的图片，可在两组各添加一次。
运行前强制预览会按颜色展示最终上传的完整图片组，最多20张，请分别核对细节图颜色。
更新后请重新为黑白T恤选择两组细节图。旧“通用细节图”仍保留给毛毯和普通T恤，不会自动用于黑白模式。
某颜色未选细节图时，扫描会提示该颜色只上传主图。原有登录、完成记录和货号记录继续保留。

颜色图上传、黑白模板预检及描述选图统一使用相同规则；真实禁用、入口缺失或多个入口仍会给出各自明确提示。
不需要更换模板，也不需要清除完成记录；关闭旧版并完整解压新版后，按原设置重新开始即可。

保留1.3.0功能
新增“黑白T恤”脚本。每个商品文件夹放2张商品主图，分别对应白色、黑色。
默认“第1张白色，第2张黑色”，可切换成“第1张黑色，第2张白色”；颜色依排序匹配，不自动识别图片内容。
点击“填入黑白模板”可使用本次提供的黑白模板，edit链接仍会转换为quoteEdit。
每次开始运行或补跑前，会强制抽取首款、中间款、末款（最多3款）逐一显示缩略图。
每款核对后点击“已核对本商品”，全部核对完才可点击“确认排序并开始”；关闭或返回调整不会启动任务。
若颜色对应不正确，返回“黑白对应”调整，并确保所有商品文件夹都采用相同的原始黑白顺序；最终上传顺序在“图片混合排序”调整。
黑白脚本只接受恰好2张原始商品图，少图/多图会提示未纳入，白色和黑色细节图请在主窗口各自添加。
每个颜色分别上传“对应颜色主图＋对应颜色细节图”，不会混入另一颜色主图；每色最多10张。
黑白模板根据网页颜色标签定位，因此即使白色和黑色行的显示顺序改变，也按对应颜色上传。

产品描述图片新增两个模式（适用于毛毯、普通T恤、黑白T恤）：
“保留模板不变”：不打开描述编辑器、不清空、不重引图片，沿用模板原有描述图文。
“重新引用轮播图”：保留原自动更新逻辑；黑白T恤会引用两种颜色的新图片，共用图片按网站图片URL去重。
旧配置默认继续“重新引用轮播图”；如要保留本次模板的工厂细节图，请主动选择“保留模板不变”。
黑白模板的完成记录和失败记录按模板独立保存，不覆盖旧版普通T恤记录；切换模板后，失败清单显示当前模板的记录。
开始前只抽取真正待处理的商品；检查模式仅核对本次处理的一款，批量模式抽取最多三款。全部已完成时不启动。

保留1.2.0功能
模板网址会自动把 edit 转为正确的 quoteEdit。商品 id 和其他查询参数保留，复制链接末尾的中文句号会自动清理。
粘贴或移开光标时即可看到转换；保存、运行、失败重试时同样校验。正确拼写是 quoteEdit。
新增“上架脚本”选择：毛毯、T恤。原配置默认沿用毛毯脚本，T恤请手动切换后使用对应模板。

T恤脚本
1. 选择“T恤”，粘贴T恤模板网址，填写“货号英文名”。
2. 英文名称以字母开头，限1–8位英文字母、数字、下划线或连字符，例如 BKShirt。
3. 货号格式为 当天日期-英文名称-序号，例如 20261023-BKShirt-0001。
4. 每款商品的每个颜色行使用独立SKC货号，同日期同英文名的序号持续累加；模板中的尺码、价格、库存等继续使用模板配置。
5. 上传顺序为商品图（第一张为主图）→通用细节图，替换颜色表的旧图片；随后点击素材图右下角刷新，核对素材图与新主图一致。
6. 产品描述仍通过原描述编辑器清空图片模块，但改为“引用skc轮播图”，只引用当前商品第一颜色的一整组新图片，避免多颜色重复。
7. 先用“发布前检查”跑1款，人工确认标题、各颜色图片、SKC货号、素材图和描述后再批量运行。
黑白T恤同样填写英文货号名，每个颜色独立分配一条SKC；模板的尺码、价格与库存设置继续沿用。
8. 新货号使用本机当前日期；同一商品重试或跨日补跑时继续使用原已分配货号，避免反复改变。同日期同英文名最多9999个货号。
货号分配记录保存在用户数据目录的 article-numbers.json，请保留该文件；不要为重试删除它。
不同电脑分别编号，英文名建议按同事区分，避免各自生成相同货号。
批次开始后使用当时的设置，自动补跑也沿用原脚本；历史失败记录会检查脚本、模板和英文名，不匹配的记录会保留并跳过。

保留此前改进
单个商品只有 1 张图片也可以正常处理；整批商品都是 1 张图时不报警。
同批文件夹的商品图片数量不一致时，会指出数量不同的文件夹并预警，但仍保留为可处理商品。
例如多数文件夹是 4 张、某款只有 1 张，会提示该款需要核对；没有唯一常见数量时会列出数量分布。
预警只比较原始商品图数量，不把通用细节图算入，也不会因为轮播图数量上限而掩盖差异。
通用细节图改为“添加图片”：可分次从不同文件夹追加，保留旧图片及手动顺序；同一路径重复选择自动跳过。
新增图片按本次文件名自然顺序追加；同名但位于不同文件夹的图片可以同时添加。
总数最多 9 张，超限时本次添加不生效，原列表保留；“预览排序”可移除单张，“清空”可全部移除。

从旧版更新
先关闭旧版，再把新版完整解压到新文件夹，双击其中的程序。
同一 Windows 用户原有设置、登录与完成记录会继续使用；旧版“至少 3 张”的配置会自动更新为允许单张。

开始使用
1. 把整个 ZIP 完整解压到本地文件夹，例如 D:\DXMUploader。
2. 双击“店小秘自动上架.exe”。不用安装 Python、Node.js、Chrome 或其他运行库，也不用运行安装脚本。
3. 选择你自己电脑上的商品图片目录，粘贴你有权限使用的店小秘 Temu 模板编辑网址。
4. 保持“发布前检查”，点击“扫描预览”，确认后点击“开始运行”。
5. 在程序打开的独立浏览器中登录你自己的店小秘账号，完成验证码。首次登录需要人工操作。
6. 核对第一个商品的标题、图片、变种和描述。检查模式停在发布前。
7. 确认正确后选择“批量定时发布”或“批量立即发布”，根据界面确认运行。

请保留整个文件夹，不能只复制 EXE。不要在压缩包预览窗口直接启动。
软件运行和浏览器自检无需下载依赖；登录、上传和发布需要正常联网以及对应店铺权限。

适用电脑
Windows 10/11，Intel/AMD 64 位。建议 8GB 或以上内存。
默认使用 1 个工作页；较高配置可在“环境与设置”中改为 2–3 页。
不适用于 Windows 7/8、32 位 Windows、macOS 或 Linux；ARM64 未验证。
没有管理员权限也可以使用，默认不修改系统 Python、PATH 或注册表。

商品图片
每个一级子文件夹是一款商品，文件夹名作为商品标题；单款也可直接选择装有图片的文件夹。
支持 JPG/JPEG、PNG、WEBP。每款至少 1 张商品图，轮播图最多 10 张。空文件夹仍会提示未纳入。
“图片混合排序”可将商品图和通用细节图穿插排列；不设置混排时默认细节图追加在商品图之后。
图片按主窗口“图片处理”设置上传；旧默认是1200×1200白底JPG，可切换原图或自定义尺寸，源文件不变。
建议先用少量商品确认模板、四个变种、图片和登录状态符合当前店铺要求。

每位同事独立配置
模板、图片目录和各组细节图均由使用者设置，发布包不包含制作者的店铺模板、账号登录、历史商品记录或素材。
配置、浏览器登录资料、完成记录、失败记录和日志自动存放在：
%LOCALAPPDATA%\DianxiaomiUploaderStandalone
可在“环境与设置 → 打开数据目录”中访问。
同一 Windows 用户的不同版本共用该目录；更新时解压到新文件夹即可保留配置和进度。
原工作台上架工具和独立版不共用数据；首次使用独立版时，需要重新配置和登录。
不要删除完成记录后重跑同一批次；继续既有批次前，请先核对店小秘后台，避免重复提交。
不要把个人数据目录打包转发；浏览器登录资料可能包含有效登录凭据。

环境与故障处理
点击“环境自检”，会验证图片转换、浏览器启动和本地自动化操作，不会进入店铺或提交商品。
环境正常仍不能运行时，检查自己的网络、账号权限、模板有效性及店小秘页面是否变化。
内置浏览器异常时，在“环境与设置”中选择已安装的 Chrome 或 Edge，或重新完整解压原发布包。
启动异常会显示错误原因并留下日志；“打开运行日志”可查看日志与自检报告。
也可双击“环境诊断.cmd”，关闭报告弹窗后查看数据目录 logs 下的 environment.json。
若出现系统安全或公司终端策略拦截，交由本公司的 IT 按实际提示处理。

卸载
关闭程序和该程序打开的浏览器，删除解压文件夹即可删除程序。
个人设置和运行记录仍保存在上述用户数据目录中；如需彻底清除，可自行备份后删除该目录。
