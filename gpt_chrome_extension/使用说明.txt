Chrome / Edge / Firefox GPT 生图助手

版本 0.4.15：开始上传时，若原添加文件按钮尚未启用，最多等待20秒再操作；等待期间持续核对原输入框、按钮、任务和草稿。持续禁用、控件替换或用户操作时停止，避免页面短暂未就绪就立刻跳过任务。动作中的禁用保护仍保留；附件失败继续自动记录结构诊断。

版本 0.4.14：附件准备失败时，自动将当前步骤的预览、文件框、浮层计数和控件状态记录到本机任务日志，帮助定位网页变化，减少手动复制页面结构。诊断只包含固定数字与状态，不包含聊天正文、文件名或图片链接。本版补充故障诊断，上传问题仍需实际任务验证；保留已有任务、图片及发送结果不明时的停止规则。

1. 先启动最新版本地工作台。扩展首次连接时会自动与本机工作台配对，不需要复制连接凭据。
2. 解压安装包后不要只拖出单个文件。Chrome 打开 chrome://extensions；Edge 打开 edge://extensions；开启开发者模式后，点击“加载已解压的扩展程序”，选择整个扩展文件夹。
3. Firefox 打开 about:debugging，在“此 Firefox”中选择“临时载入附加组件”，选择本文件夹中的 manifest.json。
4. 三个浏览器分别登录自己的 GPT 账号，各保持一个 https://chatgpt.com/ 页面。
5. 回到工作台 GPT 批量生图页，确认对应浏览器显示“已连接”。

Chrome 或 Edge 在扩展文件升级后，需要在扩展程序页面点击一次“重新加载”并刷新 GPT 页面。Firefox 临时扩展在浏览器完全退出后需要重新载入。

版本 0.4.13：按当前“＋”入口与专属输入区工具浮层的原生标记关联上传菜单，兼容没有 aria-controls 的异步浮层；入口优先识别自身标记，避免把已展开菜单里的选项当作入口。菜单文字忽略图标内部样式等装饰；页面变化时显示更具体的停止原因。已有图片、草稿、任务和额度保护保留，升级后先验证两项实际存图再恢复其余任务。

版本 0.4.12：兼容上传入口需要按下鼠标或指针才展开菜单的页面，并识别“添加照片和文件”附带“从计算机上传”副说明的菜单。保留点击式入口和菜单项兼容、当前任务与输入区归属、已有草稿和附件保护；不重复打开已展开菜单，不用页面其他位置的上传框。升级后仍先验证新聊天与原聊天续图的实际存图，再恢复其余任务。

版本 0.4.11：针对真实页面同一输入区同时存在多个图片、视频及通用文件框的情况，通过当前上传按钮或其菜单同步触发的文件框确认实际目标，兼容“添加照片和文件”等菜单文案。候选不明确时停止，不按 DOM 顺序猜测；其他弹窗、历史、延迟事件或不匹配文件类型不能取得上传资格。修复后先验证新聊天和原聊天续图，再恢复其余任务。

版本 0.4.10：增强新聊天与原聊天的附件上传兼容。只在当前输入区及其明确关联的上传控件中选文件，兼容附件托盘位于表单外的布局；附件稳定判断按文件身份核对，避免上传进度文字或标准签名更新反复重置。其他文件框、聊天历史、额外或错步骤附件仍拒绝使用。同配置连续三次明确附件准备失败时暂停该配置，等待后只放行一个探测任务。已有图片、原聊天与登录资料保留；修复后先核对新聊天和续步的实际存图结果，再恢复其余未发送工作。发送结果不明的步骤不自动重发。

版本 0.4.9：逐张生图按唯一附件卡片核对文件身份，避免嵌套缩略图、历史图片或头像被重复计数而误判上传失败。每步附件使用独立序号，兼容模板与参考图同名；实际多余附件、错误文件或仍在上传时继续阻止发送。附件须连续稳定至少 2 秒，状态中断或附件变化会重新计时。已有成图保留；仅经核对确定未发送的步骤可沿原聊天继续，发送结果不明的步骤不自动重发。

扩展仅访问 chatgpt.com 与本机 127.0.0.1:18769，权限包括 storage、downloads 和 alarms。它不读取浏览器密码或导入 Cookie，不修改浏览器指纹，不绕过网站安全验证。

开始任务后不要在执行标签页输入文字或切换聊天。扩展每个账号一次执行一套；下载完成并由本机校验后才继续。网页结构变化、验证码、上传失败或下载失败时会停止并在工作台显示“需要处理”，避免不确定时重复发送。

版本 0.3.10：修复 ChatGPT 为重复 ZIP 添加时间后缀时的附件确认；上传前检查发送框残留附件。填写提示词不再使用“全选”，发送前再次确认图片和 ZIP；只点击发送一次。刷新后若留下未发送提示词，任务停止待检查，不自动反复填写或发送。单张图片的查看器不再强求缩略图导航，并支持图片查看器中的直接下载按钮。收图仅在原对话进行，不允许首页地址覆盖原对话。旧任务里“需要处理”的记录不会自动重发，请先核对并手动重新排队。

版本 0.3.11：发送后等待 ChatGPT 将 WEB 临时地址转换为正式对话地址，再进入收图；有上下文证据时可安全接管正式地址。单张图片优先从已识别的生成图地址下载，避开查看器按钮变化。已发送任务恢复时先排队，不打断同账号正在执行的任务。

版本 0.3.33：支持每个任务上传 1 至 8 张参考图，并同时上传模板 ZIP。工作台中的“额外参考图”最多选择 7 张；扩展会按实际数量上传、稳定确认、发送和缺失附件补传。旧任务仍按一张参考图加模板 ZIP 执行。

版本 0.3.34：修复附件上传期间心跳缺少标签页会话导致后台每约 3 分钟误刷新执行页的问题；记录 GPT 的文字错误与错误提示，识别图片额度或生成失败后立即分类；连续 3 个任务无图时自动熔断 30 分钟，只放行一个探测任务，防止整批任务连续失败。

版本 0.3.35：新增首次安装自动本机配对。安装包不再包含任何电脑的连接凭据；在新电脑启动最新版工作台并加载扩展后，Chrome、Edge、Firefox 会分别取得本机凭据。凭据失效时自动重新配对。弹窗版本号改为读取实际安装版本。

版本 0.3.37：发送前页面失联只允许自动重排 1 次，第二次立即停下并等待人工检查；页面失联会计入熔断。恢复任务时优先复用原执行／恢复标签，不再因为恢复标签已经进入对话就不断新建 GPT 页面。
版本 0.3.36：修复 Edge 在发送后临时对话地址尚未转为正式地址时反复打开首页和刷新恢复标签的问题。临时地址只作为发送证据，不再用于自动恢复；正式对话失联时直接恢复原对话。同一浏览器的首页、资料库和其他普通标签不再覆盖执行标签的心跳状态，也不会降低当前账号的队列效率。

配套工作台的动态轮流规则：轮到的浏览器优先保留任务 60 秒；当它仍在执行、处于账号间隔或没有及时领取时，其他空闲浏览器可立即接手。离线接管缩短为 3 分钟，连续无图熔断按浏览器分别计算。每个账号完成后的 5 分钟间隔继续保留。
